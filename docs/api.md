# API reference

The committed [openapi.json](../openapi.json) is generated from `src/contract.ts`. Running endpoints: `/docs` for Swagger UI and `/openapi.json` for the schema. Assets are served locally. Request validation and path registration use the same definitions; CI checks the generated file byte-for-byte.

Protected requests use `Authorization: Bearer whk_...`. The CLI bootstraps an admin key; admins can create and revoke further keys. Publish-only keys cannot inspect events, delivery logs, endpoints or other keys.

| Method     | Path                                   | Scope / result                                         |
| ---------- | -------------------------------------- | ------------------------------------------------------ |
| GET        | `/health`, `/ready`                    | Public probes; readiness can return 503                |
| GET        | `/docs`, `/openapi.json`               | Public contract, no customer data                      |
| POST       | `/api/v1/endpoints`                    | Admin; URL and `event_types`; returns secret once      |
| GET        | `/api/v1/endpoints`                    | Admin; endpoint metadata                               |
| GET, PATCH | `/api/v1/endpoints/{id}`               | Admin; read or change URL, subscriptions, `enabled`    |
| POST       | `/api/v1/endpoints/{id}/rotate-secret` | Admin; returns new secret and old-secret expiry        |
| POST       | `/api/v1/events`                       | Publish/admin; requires `Idempotency-Key`; returns 202 |
| GET        | `/api/v1/events/{id}`                  | Admin; immutable delivered envelope                    |
| GET        | `/api/v1/deliveries`                   | Admin; filter `endpoint_id`, `event_id`, `status`      |
| POST       | `/api/v1/deliveries/{id}/replay`       | Admin; only failed deliveries; preserves history       |
| GET        | `/api/v1/attempts`                     | Admin; filter `endpoint_id`, `event_id`                |
| GET, POST  | `/api/v1/keys`                         | Admin; list metadata or create key                     |
| DELETE     | `/api/v1/keys/{id}`                    | Admin; revoke key, including caller's own key          |

List endpoints accept `limit` (1–100, default 25) and `offset` (0–1000000, default 0). Results are arrays in ascending creation/ID order; attempts use start time/ID. Offset pagination is convenient for this bounded single-installation API, but is not a snapshot across concurrent writes. Invalid identifiers return 400; missing single resources return 404. Unknown body fields are rejected; unknown query parameters are ignored.

## Register and publish

```json
{
  "url": "https://receiver.example/hooks",
  "event_types": ["lead.created", "lead.updated"]
}
```

`receiver.example` is a fictional placeholder; registration requires a resolvable allowed destination. The secret is generated by the service, never chosen by callers. Save it at the receiver immediately; list/get endpoints never disclose it.

Publish body, with `Idempotency-Key: fictional-lead-001`:

```json
{
  "type": "lead.created",
  "data": { "name": "Fictional Customer", "source": "example" }
}
```

Response: `{"id":"<uuid>","duplicate":false}`. A matching retry returns the same ID and `duplicate:true`, still 202. A reused key with different type/data returns 409. Idempotency keys are organisation-wide, case-sensitive, 1–200 printable non-space ASCII characters. Event types are 1–100 letters, digits, underscores, dots or hyphens. Subscription arrays allow 1–100 unique types; there are no wildcards.

The emitted JSON envelope contains `id`, `type`, `created_at` and `data`. Its exact bytes are stored once and reused on retries. The timestamp header and signature are regenerated per attempt. A publish with no matching subscriptions is still stored; registering a subscriber later does not backfill it.

## Pause, failures and replay

`PATCH {"enabled":false}` suspends claims and retains work. The automatic circuit pause is visible as `paused:true`; `enabled` can remain true. `PATCH {"enabled":true}` clears either kind of pause and resets consecutive failures. A request already in flight can finish after disabling.

Get `/api/v1/deliveries?status=failed` for the failed queue, then POST its replay path without a body. Replays reset the cycle budget but keep IDs and attempt history. A paused endpoint stays paused after replay until explicitly re-enabled. Concurrent replay requests: the first succeeds, the second returns 409.

Attempt states are `started`, `succeeded`, `failed`, or `unknown` after an expired lease. Code/duration/body/error/finish time are nullable until known. Error categories include `http_status`, `timeout`, `response_too_large`, `connection_error`, `response_error`, `response_aborted`, `destination_refused_or_dns_error`, `signing_error` and `lease_expired`. Log text is an excerpt, not the full response. Query history per endpoint or per event to see every fan-out and retry.

Errors use `{"error":"message"}`. Validation errors are 400, invalid/revoked keys 401, scope violations 403, state conflicts 409, excessive bodies 413 and unexpected failures 500. Readiness uses `{"ok":false}` with 503. Detailed internals and credentials are not included in errors.
